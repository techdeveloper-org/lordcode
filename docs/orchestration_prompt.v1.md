## YOUR TASK

**Build LordCode**: a standalone, multi-provider agentic AI coding CLI tool. It is powered by `claude-global-library`'s full capability set — 89 domains, hundreds of specialist agents, hundreds of skills, a Master Knowledge Graph, and a 23-node orchestration decision tree — used as LordCode's reasoning/orchestration **backend**. The library is consumed, not duplicated: `claude-global-library` keeps evolving independently; `lordcode` vendors/references/packages it (exact mechanism is an open architectural question for Phase 1 — see CONSTRAINTS).

**What makes this a real competitor, not a wrapper:**
1. **Multi-model routing** (Pattern 20, Domain 23) — LordCode does not lock a user into one vendor. It selects among OpenAI/Anthropic/other models per task via a real router (cascade, contextual bandit, classifier, or embedding-similarity topology — Phase 1 decides which, math-backed via `genai-routing-mathematician`), not a single hardcoded provider call.
2. **Agent/skill depth as the differentiator** — where Codex CLI and generic OpenRouter clients have a single model loop, LordCode's loop can route a task to one of hundreds of grounded specialist personas (real M1–M6 math, real worked examples, real operating rules per agent) via the same persona-injection contract `ORCHESTRATION_TEMPLATE.md` STEP 0.05 defines for this library today — LordCode IS that dispatch contract, packaged as a product.
3. **A real runtime control loop** (Pattern 50, Domain 50, Harness Engineering) — LordCode needs its own agent-loop lifecycle, tool mediation, stop conditions, budget control, retry/circuit-breaker, and eval/regression harness. This is not optional infrastructure; it is the thing that makes LordCode reliable enough to compete rather than a fragile prompt-chaining demo.

**Explicit non-goals (do not silently expand into these):** LordCode is not itself a new foundation model (no training/fine-tuning in scope — Domain 22 Foundation Model is out of scope unless a future OAQ changes this); it is not this document's job to pick a monetization/pricing model (flagged as an open question, not assumed).
